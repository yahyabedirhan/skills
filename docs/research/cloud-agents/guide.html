3The words

The terms this page uses

You will see these words in every file. Each one has a plain definition here, and an example from this research.

Spec and ticket
A spec is a GitHub issue that describes one piece of work. A ticket is a GitHub issue for one part of that work.Spec #45 started this research. #13, #15 and #16 are build tickets.
Effort
One piece of work: a spec, its tickets, and one pull request that delivers them.This research is an effort: spec #45 and its tickets.
Orchestrator
The agent session that runs an effort. It gives each ticket to a delegate. It collects the commit of each delegate. At the end, it opens the pull request.Today an orchestrator runs on the Mac or on the VPS.
Delegate
An agent that does one ticket and reports back to the orchestrator. To delegate is to give a ticket to such an agent.Hosted agents like Codex can be delegates. They cannot be orchestrators.
Sub-agent
An agent that another agent starts inside its own session. A delegate is often a sub-agent.In a cloud session, a sub-agent cannot start its own sub-agents.
Handover and handoff
A handover passes work from one session to a new session. The old session writes a handoff file, commits it and pushes it. Then it starts the new session with a one-line prompt that points at the file.The open question: how to start that new session on a machine other than the Mac.
Settle
To finish an effort after you approve its pull request. The settle-effort skill merges the pull request, does the follow-ups and closes the spec and tickets. Its old name was close-effort.Firstmate idea 2 changes how settle-effort merges.
Worktree and Treehouse
A worktree is a second working copy of the same repository, on its own branch. With worktrees, several agents work in parallel and do not touch each other's files. Treehouse is the tool that makes and frees worktrees.The Mac and the netcup VPS both have Treehouse now.
Herdr
A terminal multiplexer for coding agents. It has workspaces, tabs and panes. Each pane can hold an agent that you can list, read and prompt.Version 0.9.2 added herdr --machine, and the plan uses it. Version 0.9.3 runs on the Mac and on both VPSes.
Saved machine
Another computer that Herdr knows by a label. From the Mac, herdr --machine <label> controls the Herdr on that computer.The saved machines are netcup-vps and hetzner-vps.
VPS
A virtual private server: a small Linux machine that you rent by the month. It stays on when your laptop is closed.Your first VPS was Hetzner's smallest shared plan: 2 vCPU and 4 GB. Since 2 October, the main VPS is a netcup VPS 1000: 4 vCPU and about 8 GB. Both run Claude Code in Herdr.
Harness
The program that runs an agent model and gives it tools.Claude Code, Codex and opencode are harnesses.
Skill and global instructions
A skill is a packaged set of instructions for one kind of task. Global instructions are the rules that every session on a machine reads.Your skills come from this repository. Your global instructions are in ~/.claude on the Mac.
set-up-machine
The skill that installs your skills, global instructions, rule table and hook on a machine. Then it checks them with verify.py.It ran on the netcup VPS on 2 October.
Cloud session
A Claude Code session that runs on Anthropic's machines, not on yours. Each one gets a fresh virtual machine (VM). It continues when the laptop is closed. Anthropic takes the VM back when the session is idle.You start one from claude.ai, the phone, the Desktop app or claude --cloud.
Routine
A saved Claude Code setup: a prompt, repositories and connectors. A schedule, an API call or a GitHub event starts it as a cloud session. It is a research preview.Its API trigger is the one documented way for an agent to start cloud work. A cloud session also has a create_session tool, but nobody has tested it.
Project and thread
A Claude Code project runs several cloud sessions for one goal. Each session is a thread, with its own branch and pull request.A thread that hits a usage limit waits for the next usage window.
Auto-fix
A cloud session that watches a pull request. It pushes fixes for failed checks and for review comments. It needs the Claude GitHub App./autofix-pr starts one from the terminal.
Usage window
The period in which your Claude plan allows a fixed amount of use. The plan has a five-hour window and a weekly limit.Inside the windows, a ticket costs you no extra cash.
Promo credit
A one-time credit from Anthropic for cloud sessions: $100 on Pro, $250 on Max. Cloud sessions use it before they use your plan.You decided to spend it (D12).
Probe
A small, safe test that an agent runs to read facts about a machine. A probe changes nothing.#78 ran probes inside a cloud session.
Remote Control
A Claude Code feature. It lets you, or another session, reach a running session through Anthropic's servers.Experiment E5 tests it between the Mac and the VPS.
shipyard ping
A command that an agent on a VPS runs to send you a short message. The shipyard app in the Mac's menu bar shows it.We tested it from both VPSes on 3 October.
Track
One line of work in the plan. There are two tracks in parallel: the VPS track and the cloud track.Your answer to D1 started both tracks.
Gate
A condition that must be true before the vision can work. A gate is passed when the condition is true.Four gates are on the vision slide. One is passed.
Decision and experiment
D1 to D13 are the decisions the research asks you to make. E1 to E20 are the experiments it proposes, to answer what the documents do not.E16 tests a setup script that installs your skills in a cloud session.
Synthesis
The research file that puts all results side by side and turns them into decisions. Its file is README.md.Read it first.
Firstmate, first mate, crewmate, captain
Firstmate is an open-source tool that runs a crew of agents. The first mate is its one supervisor agent. A crewmate is a worker agent for one task. The captain is you, the person who talks to the first mate.How Firstmate works explains it.
Brief
A file that tells a worker agent what to do: the task, the rules and the definition of done.In Firstmate, the first mate writes one brief for each task.

5What we found

Seven findings, one line each

  1. The Mac stays home. Only the Mac has every harness, the current skills, Treehouse, a browser and a working notification. Today, no other place is better for an orchestrated effort. Synthesis

  2. The VPS was one upgrade away. Now it runs orchestrators. On 29 September it needed four things: a newer Herdr, your current skills, a worktree tool and a way to notify you. update 3 Oct The netcup VPS has all four. Two shipyard efforts ran there after a handover by hand. Synthesis

  3. Claude Code's cloud is good for tasks. It is almost ready for efforts. A test from inside showed this: it pushes a branch that it names, opens pull requests and has a headless Chromium. Your skills load after a setup script installs them in the VM's home folder. Three limits stay. Idle VMs still lose background work. Sub-agents cannot start their own sub-agents. A start by an agent is untested. Probe file

  4. Other hosted agents are delegates, not orchestrators. Codex, Cursor and Copilot each take one prompt on one branch and return a pull request. Try Claude Code's cloud first. None of them is worth a sign-up before that. Providers file

  5. Managed Agents is a developer API, not a better cloud session. It bills API tokens and session-hours, in addition to the plan. It does not load CLAUDE.md, skills, hooks or the Agent tool. Its one advantage is a self-hosted sandbox on the VPS. That is worth only a trial with a budget limit. Managed Agents file

  6. On the old VPS, RAM was the limit. It had 4 GB and no swap. When memory ran out, the system killed processes. Hetzner's rescale did not offer a bigger shared plan. update 3 Oct The netcup VPS has about 8 GB with zram and swap. Its peak in a trial was 4.4 GB. Now its slower cores are the limit. Sizing file

  7. Borrow from Firstmate. Do not adopt it. Take three ideas from it. First, a status file for each worker. Second, a readiness check before work goes to another machine. Third, a rule: an unreachable machine is "unknown", never a reason to move the work elsewhere. Firstmate file

6Your questions, answered

The questions in the spec, with their answers

Spec #45 asked 28 questions. Here they are in four groups, with a line or two for each. Open a group to read it. Use the links under it only when you want more detail.

Questions 1-11Claude Code's cloud sessions
What machine does it run on?
A fresh Ubuntu 24.04 VM for each session: 4 vCPU, 15.7 GiB of RAM and 30 GB of writable disk. The session runs as root. Anthropic takes the VM back when it is idle. Only the pushed commits and the conversation stay. first-hand
Which tools, and can it install more?
A broad toolchain, but no gh CLI. The setup script of the environment runs as root before the session starts. The platform caches the result. So the script can install anything.
Can it reach the web and drive a browser?
By default, web access goes through an allowlist ("Trusted"). Each environment can switch to Full or Custom. WebFetch obeys the list, and WebSearch works. A headless Chromium comes pre-installed. It works after it trusts the certificate of the network proxy. first-hand
Does my setup load there?
  • Yes: the repo's CLAUDE.md (and so AGENTS.md), the repo's .claude/skills, and the skills you enabled on your claude.ai account.
  • Only with one repository: repo hooks, permission rules and .mcp.json.
  • No: anything in your laptop's ~/.claude: global instructions, skills, hooks and your own MCP servers.
  • The way in: skills in the VM's own ~/.claude/skills load, even in the middle of a session. So a setup script can bring yours (D6).
GitHub: which branch, can it push and open a PR?
It starts on the branch that you started it from. It can push to that branch, to its own claude/… branch or to a new branch that it names. A push to an existing branch from another machine is untested (E20). It opens pull requests with its Create PR button or with GitHub tools. GitHub's REST API works for the attached repo. GraphQL is blocked. first-hand
How is it started, and can a local agent start one?
You can start one from claude.ai, the phone or the Desktop app. You can also run claude --cloud "task" in a terminal. It prints the session's URL and exits. For an agent, the documented way is a routine's API trigger. Two other ways are untested: claude --cloud from an agent's shell, and create_session from inside a cloud session (E11, E17).
Can it run a whole effort with sub-agents?
Partly. Sub-agents work, but only one level deep. Background work stops when Anthropic takes back an idle VM. A permission prompt stops a run that nobody watches. Try this first: one effort in one session that you watch, after the skills load (E16). Claude Code projects add a coordinator that runs threads in parallel.
How do I watch it, answer it and hear from it?
Watch and answer on claude.ai or in the Claude app. claude -p "<msg>" --cloud <id> sends a follow-up from any machine. No CLI command prints its status. But inside a cloud session, list_sessions reads every session on your account. Today the pull request tells you that the work is done or blocked. The session's own phone push is half tested (#80).
Can it come back to my machine?
claude --teleport <id> copies its branch and conversation into a local checkout. The docs do not say that the cloud session stops (E12).
What does it cost?
It uses your plan. The VM costs nothing extra. Anthropic spends the one-time promo credit first. You saw the credit go down after #78's session. Routines have a daily limit on runs.
Scheduled or triggered agents?
Routines. A routine is a saved prompt, repositories and connectors. A schedule, an API call or a GitHub event starts it as a cloud session. Routines are a research preview. By default, a new routine gets every connected connector, with write access. So check the connectors of each routine.

How two efforts went to a VPS by hand

shipyard 0.0.5 went to the Hetzner VPS (Herdr 0.9.0, over SSH). shipyard 0.0.6 went to the netcup VPS (Herdr 0.9.3, mostly herdr --machine). Both merged. #13 will make these steps automatic. No skill does them yet.

  1. Push the handoff from the Mac.
  2. Install the project's toolchain on the VPS. sudo runs in a Herdr tab, and you type the password there (#148).
  3. Lease a worktree with treehouse.

11How Firstmate works · research #88

One supervisor, many workers, and files instead of memory

One agent, the first mate, never writes code. It writes a brief file and starts a crewmate in its own terminal tab and worktree. After that, they talk only through files. A bash script, the watcher, uses no tokens. It wakes the first mate only when something needs it. Each piece of state that must survive a crash is a file, and one script owns each file.

  2. Brief

Captain and first mate
You talk only to the first mate. It is a long-running agent, one on each machine. It sorts new work, writes briefs, supervises the workers and asks you for decisions. It never changes a project itself.
Crewmate
One visible terminal agent for each task. It can be Claude, Codex, opencode or another harness. Each crewmate works in its own Treehouse worktree, on the branch fm/<id>.
Brief
data/<id>/brief.md holds four things:
  • your exact words, as acceptance criteria;
  • the build spec;
  • an isolation check;
  • the definition of done.
When a worker restarts, it reads the same brief.
Status file
The worker adds a one-line event to state/<id>.status, but only when its phase changes. The events are working, needs-decision [key=…], blocked, paused, done and failed. A decision stays open until a matching resolved line closes it.
Inbox and doorbell
To steer a worker, the first mate writes a numbered file in state/<id>.inbox/. Then it types one fixed line, the doorbell, into the worker's pane. The worker confirms each message: it moves the file to handled/. If a message stays unread, the watcher rings again. After that, it reports the message to the first mate.
Watcher and wake queue
fm-watch.sh is a bash loop that checks every 15 s. It ignores routine events and queues only the events that need action. The first mate confirms a wake only after it acts on it. On Claude, a second headless session now handles the routine wakes.
Secondmate
A complete Firstmate home on another machine, which the first mate reaches over SSH. A "doctor" script checks that the machine is ready. When the first mate cannot reach the machine, its state reads unknown, never dead. Work never moves back to the local machine without a message.

WorkflowsThe main flows, step by step
Intake
The first mate makes these choices, then files the backlog item:
  • the project;
  • ship (a change, the default) or scout (a report, never a PR);
  • the delivery mode: no-mistakes, direct-PR or local-only;
  • the merge rule: you approve every merge, or "yolo" merges green work;
  • the harness.
Independent work starts at once.
Brief and spawn
The first mate makes the brief from a template and fills it. Then fm-spawn.sh does these steps:
  • take the locks;
  • open a tab;
  • run treehouse get and wait for a clean worktree;
  • accept the trust prompt in advance;
  • install hooks;
  • write state/<id>.meta;
  • move the item to In flight;
  • start the agent with the brief.
The worker's loop
The worker:
  • checks its isolation first;
  • makes a branch and works;
  • writes a status line only when its phase changes;
  • reads the inbox at checkpoints and when the doorbell rings;
  • touches a file that the watcher reads, at the end of each turn.
Decisions
The worker writes needs-decision and stops. The first mate makes the clear decisions itself. It asks you only about a larger scope, a product choice or destructive work. Then it holds the item for you. It sends your answer to the worker with --resolve-key.
Delivery and merge
A task is "done" only when the worker has pushed its head. The scripts register the PR and poll it. The merge waits for your word. Then it checks the live state and merges with --match-head-commit. So if someone pushes after your review, the merge fails.
Teardown
The script stops if any work has not landed. Then it closes the tab, returns the worktree and marks the item Done. The brief and any report stay.
Crash and restart
A new session takes a lock, or it stays read-only. Then it rebuilds its state from the meta records, the status logs and the wake queue. For a stuck worker, the first mate takes these steps in order: look at its pane, answer, interrupt, restart. The restarted worker uses the same worktree and the same brief, plus a progress note. "A restart must be a non-event."
Remote secondmates
The first mate sets up a home on the host after a readiness check. Each call runs a checked script over SSH. Requests go into the remote inbox with a correlation id. Replies come back as a copy of the remote status file. When the first mate cannot reach a host, the host reads unknown.
Traced end to endOne task in 23 steps, condensed

The captain types "the login page redirects to / instead of /dashboard; fix it in acme-web". The setup: direct-PR mode, the Herdr backend, and a merge only when the captain says so.

  1. The first mate resolves the project and mode, files login-redirect-k3 in the backlog, and writes the brief.
  2. fm-spawn.sh opens a Herdr tab, gets a Treehouse worktree, writes the meta record, and launches Claude with the brief.
  3. The worker checks that it is isolated. It makes a branch, reproduces the bug and adds working. The watcher handles this event without waking the first mate.
  4. The worker finds two possible fixes and adds needs-decision [key=redirect-target]. The watcher queues a wake.
  5. This is a product choice. So the first mate holds the item and asks the captain in one line, with a recommendation.
  6. The captain answers. The first mate records the answer and sends it through the inbox with --resolve-key. The worker reads it and confirms it.
  7. The worker pushes, opens a ready PR and adds done: PR …. The first mate checks the state and registers the PR.
  8. The captain says "merge". fm-pr-merge.sh checks live state and merges with --match-head-commit.
  9. fm-teardown.sh proves it landed, closes the tab, returns the worktree, and marks the item Done. One line to the captain with the PR's URL.
