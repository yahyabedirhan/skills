Where can your agents work when the laptop is closed?

Six research files and one synthesis map every place an agent could run for you: your Mac, your VPS, Claude Code's cloud and the other hosted agents. This page is the way in. It opens with where this could lead, explains the words, shows the landscape, gives you the result in a few lines, and then guides you through the files in the order worth reading them.

1The vision

The pitch, not the findings

Close the laptop. The work keeps shipping.

Picture one day with a fleet: you think in the morning, a crew builds while you're out, and your phone only buzzes when a decision is yours. None of it is built yet. Every piece of it is documented or proposed in the research.

  1. 108:30, on the Mac

    Think it through with one agent

    Coffee, one thinking session, a spec and its tickets. Then a single line hands the whole effort over. How

  2. 209:15, on the VPS

    An orchestrator takes the wheel

    It starts in a Herdr tab on your server, after a quick machine status check, and runs its crew in the tabs beside it. How

  3. 310:00, in the cloud

    The crew fans out

    Self-contained tickets go to cloud sessions, each on its own fresh 16 GB machine, all at once. Codex, Cursor or Copilot can take a ticket too. An agent starts cloud work through a routine: untested (E11) How

  4. 413:30, on your phone

    A decision needs you

    Your phone buzzes over lunch. You read the question in the Claude app, answer in one line, and the crew carries on. Remote Control push: untested (E5) How

  5. 516:00, in the cloud

    GitHub wakes a routine

    A pull request opens and a routine fires on the event. Auto-fix watches the pull request and pushes fixes for failing checks and review comments. How

  6. 618:30, back on the Mac

    A reviewed pull request is waiting

    Your Herdr window has shown every VPS agent's state all day. Each commit links back to the session that wrote it, and --teleport pulls a cloud session to your terminal if you want to take over. How

  7. 702:00, while you sleep

    The night shift

    A scheduled routine runs its nightly job while the VPS orchestrator keeps going. Breakfast comes with a queue of pull requests. How

The edge of the possible

Parallel crews
A Claude Code project runs a coordinator with threads side by side, each on its own branch, each opening and auto-fixing its own pull request. Cloud file
Overnight runs
The VPS and the cloud don't sleep when the laptop does. A project thread that hits a usage limit waits and picks up again in the next window. Cloud file
Work that starts itself
A routine is a saved prompt that fires on a schedule, an API call or a GitHub event, with nobody at the keyboard. Cloud file
Agents that talk across machines
With Remote Control on, a Mac session and a VPS or cloud session can message each other both ways, with no tunnel into your Mac. claude -p … --cloud <id> nudges a cloud session from any machine. Untested (E5) Delegation file
A fleet at a glance
Herdr on the Mac keeps every VPS agent's state live, and a project's overview sorts threads into Working, Waiting on you and Ready for review. Firstmate adds a status file per worker, so nothing is lost when an agent restarts. Firstmate file

Next: why this research

2Why this research

Your setup works on the Mac. Beyond it, almost nothing was mapped.

“Each time work has moved between machines so far, it worked only because the maintainer relayed state by hand.”

From the problem statement of spec #45.

A VPS set up by hand

A small server already runs Claude Code in Herdr, but nobody had checked what an agent there can and can't do compared with the Mac.

Hosted agents, unmapped

Claude Code, Codex, Cursor and GitHub all run agents in their own clouds. Their machines, tools and limits were unknown, and cloud credits sat unused.

Three build tickets waiting

Handing work to the VPS (#13), continuing an unfinished effort (#15) and seeing each other's state (#16) were blocked until this map existed.

So the effort was research only: no skill, instruction or machine was changed. Each ticket answered one area from official documentation, plus a few safe, read-only probes. A final synthesis put everything side by side and turned it into decisions for you.

Next: the words you need

3Eight words

The few terms the research leans on

You'll meet these in every file. Each one in plain language, with where it shows up here.

Effort
One piece of work described by a spec and split into tickets, delivered as one pull request.This research is an effort: spec #45 and its tickets.
Orchestrator and delegate
The orchestrator runs an effort: it hands each ticket to a delegate, collects each delegate's commit, and opens the pull request. A delegate does one ticket and reports back.Hosted agents like Codex fit the delegate role, not the orchestrator's.
Handover
One session passing work to a new session: it writes a handoff file, commits and pushes it, then starts the new session with a one-line prompt pointing at it.The open question is how to start that new session somewhere other than the Mac.
Worktree
A second working copy of the same repository on its own branch, so several agents can work side by side without touching each other's files. Treehouse makes them on the Mac.The VPS has plain git but no Treehouse yet.
Herdr
A terminal multiplexer built for coding agents: workspaces, tabs and panes, each able to hold an agent you can list, read and prompt. It can save another machine and drive it.Version 0.9.2 adds herdr --machine, which the plan builds on.
VPS
A virtual private server: a small Linux machine rented by the month that stays on when your laptop is closed. Yours is Hetzner's smallest shared tier, 2 vCPU and 4 GB.It already runs Claude Code in Herdr.
Cloud session
A Claude Code session that runs on Anthropic's machines instead of yours. Each one gets a fresh virtual machine, keeps running with the laptop closed, and is reclaimed when idle.Started from claude.ai, the phone, the Desktop app or claude --cloud.
Routine
A saved Claude Code setup (a prompt, repositories, connectors) that runs as a cloud session on a schedule, an API call or a GitHub event. A research preview.Its API trigger is the one documented way for an agent to start cloud work.

Off the line: Firstmate

Not a place, but a different way to run a crew. It's an open-source “agent distro” by the author of Treehouse: one agent you talk to (the first mate) starts visible terminal agents, each with its brief and status kept on disk, on your machine or on an SSH host. It runs wherever it's cloned. The research reads it for ideas to borrow.

Summarised from the capability matrix in the synthesis. The full matrix, with a source behind every cell, is here in VS Code.

Next: what we found

5What we found

Six findings, one line each

  1. The Mac stays home. It's the only place with every harness, current skills, Treehouse, a browser and a working notification. Nothing researched beats it for an orchestrated effort today. Synthesis

  2. The VPS is one upgrade away. Web, GitHub and Claude Code already work there; it needs Herdr 0.9.2, your current skills, a worktree tool and a way to notify you. VPS file

  3. Claude Code's cloud is good for tasks, not yet for efforts. Your skills don't load there as things stand, idle VMs lose background work, and a local agent can't start a session with claude --cloud. Cloud file

  4. Other hosted agents are delegates, not orchestrators. Codex, Cursor and Copilot each take one prompt on one branch and return a pull request; none is worth a sign-up before Claude Code's cloud is tried. Providers file

  5. On the VPS, RAM is the limit, not CPU. With no swap, running out of memory kills processes; the next tier up costs €3 more a month, but Hetzner may refuse the rescale for now. Sizing file

  6. Firstmate is worth borrowing from, not adopting. Take its status file per worker, its readiness check before handing work to another machine, and its rule that an unreachable machine is unknown, never a reason to fail over. Firstmate file

One gap runs through all of it: there are no first-hand facts about the cloud VM. Of the two allowed cloud probes, the first exited without evidence of a session and the second was refused by the agent's own permission check. What the cloud files say comes from Anthropic's documentation.

8Try it yourself

Experiment E1: the one cloud probe only you can run

The research was allowed two small cloud sessions and got nothing out of them. Starting one with claude --cloud needs an interactive terminal, which an agent doesn't have. So the second allowed session is yours.

You start one read-only session against this public repository, on a throwaway branch. It reports what the cloud machine really is and pushes its report to that branch. Then you delete the branch.

  1. Before you start, you need a claude.ai sign-in, and the Claude GitHub App or a /web-setup connection so the session can push back.
  2. Push a throwaway probe/… branch.
  3. Run claude --cloud with the read-only probe prompt shown here.
  4. Note what the CLI prints: whether it shows a session ID or URL is itself an open question.
  5. Read the report on the probe branch, then delete the branch.
Your terminal, in this repository
# a throwaway branch on GitHub
git switch -c probe/cloud-agents-e1
git push -u origin probe/cloud-agents-e1

# the probe itself, interactive
claude --cloud "Read-only probe. Report uname -a, nproc, free -h, df -h /, whoami; versions of git gh node python3 go docker and any chromium/chrome/playwright; which skills you can see and whether AGENTS.md loaded; whether WebFetch of https://code.claude.com works; whether you can spawn one sub-agent. Write the answers to probe.md, commit it and push it to probe/cloud-agents-e1. Change nothing else."

# afterwards: remove the branch
git switch -
git push origin --delete probe/cloud-agents-e1
git branch -D probe/cloud-agents-e1

What it settles: the VM's real size and user, whether a browser exists, whether web tools work on the default network setting, whether skills and AGENTS.md load, and whether it can push to another branch.

Cost and risk: one small session of plan usage or promo credit. Low risk: public repo, throwaway branch, read-only prompt.

Worth adding to the same run, from the synthesis: ask it to list its skills, try a push to a second branch, say “notify me when done”, and run gh api …/issues/45/sub_issues. To test one way of carrying skills (D6), give the cloud environment a setup script that installs them first. A zero-cost warm-up is E2: look on claude.ai for a session left by probe 1, and read the credit's balance and terms.
