# Decisions: Claude Code plugins

How the skills in this repo are published as Claude Code plugins, from `.claude-plugin/marketplace.json`. This file is for maintaining the marketplace and is never installed. The first plugin's own decisions are in `wispr-flow-dictionary.md` (2026-09-28, plugin). Add an entry for each new decision: the date, what was decided, and why.

## 2026-10-01

From [#34](https://github.com/yahyabedirhan/skills/issues/34). Checked against Claude Code 2.1.286 and its docs ([plugins reference](https://code.claude.com/docs/en/plugins-reference), [marketplace reference](https://code.claude.com/docs/en/plugins/marketplace-reference), [host a marketplace](https://code.claude.com/docs/en/plugins/host-marketplace), [skills](https://code.claude.com/docs/en/skills)).

- **One plugin per skill, unless the skills name each other; then one per family.** The effort workflow's skills hand off to each other by name, so they ship as one plugin, `effort-workflow`, and none of its pointers dangle. `show-me`, `low-level-design`, `system-design`, `email` and `wispr-flow-dictionary` stand alone, so each is its own plugin and a user takes only what they want. A skill is in one plugin only, because a skill in two plugins loads twice when both are installed.
- **A family plugin is rooted at `skills/` and lists its folders.** Its entry has `"source": "./skills"` and a `skills` array of `./<skill>` paths. A `skills` key adds to the default `skills/` scan instead of replacing it, so a source of `./` would load every skill in the repo; tested with `--plugin-dir`. Rooted at `skills/`, the default scan looks for `skills/skills/`, which doesn't exist, and only the listed folders load. A single-skill plugin keeps the `wispr-flow-dictionary` shape: `source` is the skill's folder.
- **`effort-workflow` depends on `show-me`.** `/orchestrate-effort` uses it to show the plan, and a `dependencies` entry installs it with the family. The family's other companions, the `grilling`, `prototype`, `tdd` and `code-review` skills from mattpocock/skills, aren't plugins from a marketplace this one trusts, so the README keeps naming them.
- **Agent setup is not a plugin.** `/set-up-machine` wires the pre-tool hook to the absolute path of its installed copy, under `~/.agents/skills` or `~/.claude/skills`. A plugin lives in a cache folder that changes with each update, so the wired path would break. The family also exists to install skills for several harnesses with `npx skills`, which a Claude Code plugin can't do. `/maintain-environment`, `/set-up-project` and `/skill-recap` stay with it, since they name `/set-up-machine`.
- **Handover prompts stay as they are.** A plugin skill's full name is `/<plugin>:<skill>`, but Claude Code also runs it by its bare name when no other skill has that name. Tested with a user-invoked plugin skill: `/zqa-one some/path.md` ran it with the argument. So `/orchestrate-with-handoff <handoff>` starts the plugin's skill, and the skills keep naming each other without a prefix. The model sees the prefixed names in its skill list and matches them to the bare names in the text.
- **Installing a skill both ways stays a README warning.** A plugin skill and the same skill installed with `npx skills` both load, and the bare name runs the `npx skills` copy, so plugin updates to it go unseen. Claude Code has no way for a plugin to detect or block this, so the README tells the user to pick one and how to remove the other. The maintainer installs with `npx skills`; the plugins are for other Claude Code users.
- **Plugin names are the skill's name, or the family's name in kebab case.** A name is what users type in `/plugin install` and what `enabledPlugins` stores, so a rename breaks installs. The marketplace's `renames` map, from Claude Code 2.1.193, can carry users to a new name or record a removed plugin as `null`; use it if a name must change, rather than treating names as impossible to change.
- **No `version` on any plugin**, as for `wispr-flow-dictionary`: each push to the default branch reaches users as a new commit.
- **Validated with `claude plugin validate --strict .`** and by loading a scratch copy of `skills/` with `--plugin-dir`. Nothing was installed; installing from GitHub end to end is left to a QA issue.
